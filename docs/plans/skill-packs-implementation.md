# Skill pack implementation

Implement the audited packs through evidence-specific checks. Existing rule IDs and report contracts remain stable. Reuse one file read, one Markdown structure, and cached repository facts. Add repository/authoring taxonomy and explicit document profiles. Never execute commands found in a document or upload private profiles implicitly.

Delivery order:

1. Source and repository facts: Markdown structure, manifests, paths, TS/JS source support, file-local import facts.
2. Deterministic README, instruction, skill, package, architecture, and document checks with fail/pass/unknown fixtures.
3. Context-bounded copywriting and instruction questions; shared patterns retain one canonical owner.
4. Skill discovery covering all folders, with a durable disposition ledger for every source rule. Distinguish implemented checks, existing overlap, external-tool integration, runtime evidence, and editorial judgment.
5. Full verification and offline smoke runs. No live provider calls or private profile reads in this implementation.

Browser flows, external service state, private-voice fidelity, and distributed correctness require evidence not provided by ordinary file extraction. Their ledger entries must name that evidence rather than ship a heuristic as a correctness verdict. This plan does not treat pending entries as completed implementations.
