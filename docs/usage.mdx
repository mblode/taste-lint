# Usage

## Example findings

```text
PASS: 144 active rules in data/rules

src/Orders.tsx
[MINOR] motion-transition-all (p=1.00) src/Orders.tsx:9:1
    transition-all animates every property, layout included
    transition-all
    Fix: Name the properties: transition-transform, transition-opacity or transition-colors.
[MINOR] copywriting-click-here-links (p=1.00) src/Orders.tsx:13:1
    Link text that names nothing
    Fix: Name the destination or the outcome.

2 review notes from 2 rules (never fail a run; use --verbose to list): copywriting-vague-error 1, interaction-no-error-state 1

Units: 6  |  Rules: 130  |  Act: 2  |  Review: 2  |  Unknown: 0
Jev: 2 requests, 0 cached answers, 3120 input tokens, $0.0001
FAIL - 2 rule findings meet the failure threshold
```

## Two answers per finding

- **Severity:** how bad the finding is if real, `major` or `minor`. Set by the rule, never by the model.
- **Band:** how sure the tool is. `act` fails the run. `review` is a note that never fails a run. Below that is silent.
- **Unknown:** a check that could not decide, because a value was unresolved or a precondition was unmet. Not a pass.

Act findings are listed in full. Review notes are counted by rule; `--verbose` lists them.

## Profiles

A profile is a scope. It picks files and rule domains and never changes a rule’s status.

| Profile | Files | Rules |
| --- | --- | --- |
| `product` | tsx, jsx, css, scss | copy, typography, interaction, motion |
| `writing` | md, mdx | copywriting and typography |
| `instructions` | AGENTS.md, CLAUDE.md, skills, plans | authoring and document structure |
| `code` | ts, tsx, js, tests, JSON, YAML and TOML config, GitHub workflows, `.env` files | engineering: performance, data access, test value and gaps, dead code, code quality, telemetry, sensitive data, CI |
| `all` | everything supported | the whole catalog |

Search visibility (page metadata, `metadataBase`, sitemap and robots, noindex, canonical hosts) runs under `product`, because it reads the same pages.

### The code profile

`--profile code` reviews source the way the [tidy](https://github.com/mblode/agent-skills/tree/main/skills/tidy), [test-audit](https://github.com/mblode/agent-skills/tree/main/skills/test-audit) and [ci-speedup](https://github.com/mblode/agent-skills/tree/main/skills/ci-speedup) skills do:

- **Performance:** blocking sync calls in request handlers, independent awaits run in sequence, formatters rebuilt every render, heavy libraries with native replacements.
- **Data access:** a query per item in a loop, list reads with no limit, related writes with no transaction.
- **Test value:** tests that assert nothing, compare a value with itself, check only that a mock was called, render and check presence, or snapshot a change detector. Focused and skipped tests.
- **Test gaps:** modules whose branches the tests mostly never run, where the logic can reach users or data. Reads `coverage/coverage-summary.json`, so run your tests with the `json-summary` coverage reporter first; without a report the rule reports unknown. CLI entry points and `commands/` folders are skipped, because tests that run the binary are invisible to coverage.
- **Dead code:** commented-out code, branches that can never run, flags hard-coded to one value, dependencies nothing imports.
- **Code quality:** files over 1000 lines, blocks repeated in one file, type bypasses, rethrow-only catches, comments that restate the code, placeholder residue.
- **Telemetry:** errors dropped in an empty catch, failures turned into a default with no record.
- **Sensitive data:** committed keys, credentials or personal data in logs, tokens in `localStorage`, `Math.random` for secrets.
- **CI:** pull request runs that are never cancelled or that cancel default-branch runs, full clones nothing reads, uncached installs, coverage collected on every pull request.

Tests are in scope for the rules about tests and out of scope for the rest. Minified bundles and files marked as generated are skipped. A whole file too long for one question is judged on the lines around the match.

Two scans are not lint rules. Migration planning traces flows across a codebase to write a plan: use the [planning](https://github.com/mblode/agent-skills/tree/main/skills/planning) skill. Compliance against your organisation’s policy needs that policy: write it as a rule pack (below), one question per requirement.

```bash
taste-lint lint --profile product --dry-run
taste-lint lint --profile writing docs README.md
taste-lint lint --profile product --since origin/main --output sarif > results/taste.sarif
```

`--since` keeps whole files for context and reports only findings on changed lines.

In GitHub Actions, upload the SARIF so findings land on the pull request diff. Mechanical rules need no key; add `AI_GATEWAY_API_KEY` as a secret to run the Jev questions too.

```yaml
- uses: actions/checkout@v4
  with: { fetch-depth: 0 }
- run: npx taste-lint lint --profile product --since origin/${{ github.base_ref }} --output sarif > taste.sarif || true
- uses: github/codeql-action/upload-sarif@v3
  with: { sarif_file: taste.sarif, category: taste-lint }
```

## What blocks and what reports

28 rules are `active` and fail a run. All of them are mechanical: a regex, a parsed file or a measured value decides. The other 177 are `review-only`:

- **Pattern ports** from `ui-design`, `ui-animation` and `typography-audit` that match raw source. A match nominates a candidate; it does not prove the skill’s conclusion.
- **Jev questions**, one per rule, that need a labelled corpus before they may block.

A Jev rule is promoted only by `taste-lint tune --write`, and only when the fixed threshold clears the precision lower bound on an independent holdout. No rule has been promoted yet. The loudest two were measured at 0 to 10 percent precision on real prose, which is why review notes are counted rather than listed.

## Promoting a rule

A judge nobody has checked settles hard cases with the model’s biases. Work this loop in order and repeat it; human time comes last, spent only on what the AI loop can’t settle.

1. **Get it working.** `taste-lint eval` should report `Jev: N requests` with no errors. A rejected key fails the run instead of reporting a judge that never fires.
2. **Find failure modes.** `taste-lint eval --only <rule> --split dev --disagreements` lists every row where the judge and the label disagree at the review threshold. Group them by cause first: the judge was never asked, the rubric reads plain text as a violation, or the label is wrong.
3. **Fix them with AI.** Have an agent rewrite the rule’s `question` from the dev disagreements. Confirm each wording with `taste-lint tune ab --rule <rule> --variant <file>`, then check the holdout with `eval --split holdout`. Each edit should be a general policy, not a patch for one row.
4. **Then optimise cost**, then speed: gates, preconditions and batching, measured with the same eval.
5. **Then label the residue yourself.** Export samples with `lint --samples results/blind.json` (likely failures first), label them with `taste-lint eval label results/blind.json --minutes 120`, list rubric gaps with `eval gaps`, and import with `eval labels results/blind.json --out data/corpus/<name>.jsonl`. `tune --source hand --write` then promotes the rule, or leaves it review-only, on the untouched holdout.

To reuse an AI labeller, label the same samples both ways and run `taste-lint eval agreement results/blind.json results/ai.json`. Trust its labels only for rules where the agreement lower bound clears the floor.

A wrong finding is corpus evidence. Add the unit with the correct label rather than lowering a threshold by hand.

## Rule packs

- **Typography:** straight quotes, dashes, ellipses, primes and units from `typography-audit`. Size, weight, tracking and line-height checks over resolved Tailwind classes or computed styles.
- **Copywriting:** claims without evidence, vague errors, friction CTAs, hedges and register shifts from `ghostwriter` and the ui-design copy guideline. The ghostwriter structure tells block at one sighting: participle tails (“, ensuring…”), antithesis (“it’s not X, it’s Y”) and tee-ups (“Here’s the thing”). A quoted example is never a tell. Every’s AI-tell checker contributes 19 questions, one rule each.
- **Interaction and craft:** the static checks of `ui-design/rules` as whole-file patterns. Focus traps, error and empty states, target size, i18n, lazy loading. The shadcn/lint class hygiene rules cover raw palette colours, arbitrary values and interpolated class strings.
- **Motion and product:** the `ui-animation` flag-on-sight table, `transition: all` in CSS, `will-change` misuse and `framer-motion` imports (use `motion/react`), plus the two deterministic `product-design` rules.

Every rule names the file and line of the skill or lesson it came from. `taste-lint rules list` prints tier, status and category per rule.

## Rendered mode

```bash
taste-lint lint --url https://example.com/pricing --selector main
```

Runs [style-capture](https://www.npmjs.com/package/style-capture) in headless Chromium and lints computed styles. The typography rules then judge what the reader sees rather than what the class list implies. `--selector` narrows the page.

## API

```typescript
import { runLint } from "taste-lint";

const result = await runLint({
  root: process.cwd(),
  profile: "product",
  targets: ["."],
});
console.log(result.summary, result.usage.costUsd);
```

`runLint` takes the same options as the `lint` command, all optional. Pass `evaluate` in the second argument to supply your own judge. `taste-lint schema` prints every command, flag and default as JSON. `--output json` turns an error into a `{ error, code, message }` envelope on stdout.

## Options

| Flag | Default | Description |
| --- | --- | --- |
| `--profile <name>` |  | `product`, `writing`, `instructions`, `code` or `all`; paths default to `.` |
| `--dry-run` |  | Plan and print units, requests and estimated cost without calling Jev |
| `--since <ref>` |  | Report only findings on lines changed since a Git revision |
| `--only <ids>` |  | Comma-separated rule ids |
| `--brief <file>` |  | What the product is and does. Copy that claims anything else is flagged by `copywriting-invented-capability` |
| `--exclude <globs>` |  | Comma-separated globs to skip, added to `taste-lint.config.json` |
| `--fail-on <severity>` | `minor` | Lowest severity that fails the run |
| `--fix` |  | Apply deterministic fixes to act-band findings |
| `--samples <file>` |  | Write blind labelling samples for the Jev rules that ran |
| `--output <format>` | `tty` | `tty`, `json` or `sarif` |
| `--verbose` |  | List review notes, suppressed findings and unknowns |
| `--url <url>` |  | Lint a rendered page through style-capture |

`--help` lists the rest: `--root`, `--results-dir`, `--model`, `--no-cache`, `--progress`, `--selector` and `--print-requests`. Every run saves a complete JSON report and prints its path. An incomplete run prints a retry command that reuses successful answers.

## Configuration

Optional, at `taste-lint.config.json` in the project root. The editor schema ships at `node_modules/taste-lint/data/config.schema.json`. Unknown fields and invalid types fail before evaluation.

```json
{
  "$schema": "./node_modules/taste-lint/data/config.schema.json",
  "exclude": ["docs/archive/**"],
  "docTypes": [{ "glob": "content/**/*.mdx", "type": "explanation" }],
  "tailwind": { "theme": { "body": "16px" } }
}
```

`rules` adds rule directories laid out like `data/rules`: domain folders of YAML rules. Paths resolve from the project root; `~` and `$VARS` expand.

Suppress one unit with `taste-lint-ignore: <rule-id>` on the line above. Projects that curl quotes at build time are detected; force it with `smartQuotesAtBuild`.

## Voice pack

A voice pack is a `rules` directory that checks one person’s or company’s voice. The ghostwriter profiles ship one at `$GHOSTWRITER_HOME/taste-lint`: Australian spelling, the ChatGPT link tag, unicode arrows, em dashes, stock email sign-offs, LinkedIn bait, blog exclamation marks and Slack hype, each citing its profile line.

```json
{ "rules": ["$GHOSTWRITER_HOME/taste-lint"] }
```

Rules scope themselves by glob, so a draft named `intro.email.md` gets the email checks and `blog/post.md` the blog ones. `--fix` rewrites US spelling and strips `?utm_source=chatgpt.com`. Pack rules are mechanical: no text is sent anywhere.

## Project setup

Run `npx taste-lint@latest init` in a directory with a package.json. Setup detects the package manager, installs Taste Lint as a development dependency, and adds a `taste` script. React, Next.js, Vue, Svelte and Astro dependencies select the product profile. Other projects start with writing.

- `--root <path>` selects a project directory, including one workspace package.
- `--pm npm|pnpm|yarn|bun` overrides detection.
- `--dry-run` previews setup without writes or installation.
- `--no-install` adds the script without running the package manager.
- `--agent` appends a marked section to AGENTS.md once.

Setup never asks for or stores an API key.
