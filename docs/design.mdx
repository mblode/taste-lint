# Design

## Contracts

### Rule

One YAML file per rule at `data/rules/<domain>/<id>.yaml`, with `id` equal to the filename. Fields live in `src/types.ts` (`Rule`) and are validated fail-closed by `src/rules/validate.ts`. An invalid rule aborts before any request is made.

A rule writes only what cannot be derived. The loader fills in `domain` from the category and `tier` from which of `mechanical` and `question` are present. For every unit kind but `source` it also fills `scope.include` from the unit kinds. Every rule skips tests, stories and changelogs; `scope.exclude` adds to that list.

- A mechanical section alone runs in code (`tier: mechanical`). A raw-source regex only nominates a candidate. Its match does not prove the source skill’s conclusion.
- A question alone sends one question per matching unit (`tier: jev`).
- Both together make the mechanical part a candidate filter (`tier: both`). Only units it fires on go to Jev, and the mechanical hit never surfaces alone. A whole file past the context budget is judged on a window around the first candidate match, under the file’s unit id.
- Anything that counts, compares or measures is a code rule in `src/rules/code/*.ts`, with `check(unit)` in place of `mechanical`. The loader returns both kinds in one list.
- `preconditions.notGenerated` skips minified bundles and files that say they are generated.
- `mechanical.absent` pairs with `regex`. The rule fires only when `regex` matches and `absent` matches nowhere in the unit.
- `mechanical.codeOnly` masks strings and comments in a JS or TS `source` unit, so a pattern quoted in a string or a comment never fires.
- `thresholds.act` and `thresholds.review` are per rule. At or above `act` fails the run; between the two prints a review note; below is silent.
- `severity` (`major` or `minor`) says how bad a finding is if real. It is independent of probability.
- `source` points at the exact file and line the rule was harvested from. `handWritten` lists the keys `scripts/port-rules.ts` must not overwrite.
- Raw-source candidates carry a `review` procedure: applicability, exceptions, evidence and verification. They stay review-only under every tuning overlay and report as `assessment: candidate`.
- `data/rules/tuning.json` overlays `thresholds.act` and `status` per rule. Only `tune --write` writes it.

### Unit

`src/types.ts` (`Unit`): one extracted piece of text, one class list, or one whole TSX, JSX or CSS file (kind `source`). Each has `file`, a 1-based `line` and `column`, UTF-16 source offsets and `inCode`. `fixRanges` marks the prose a fix may rewrite; it is absent when nothing can be rewritten safely. `context` carries the heading above, doc type, element and role. Class lists also carry resolved typography and text-bearing neighbours. `id` is a stable hash used for cache keys and SARIF fingerprints.

### Jev request

`src/map/jev.ts` speaks `POST /v1/systemone` with `\{ model, state, questions \}`. With only `AI_GATEWAY_API_KEY` set, the same request goes through the Vercel AI Gateway evaluation route. State is a labelled string built from the unit and only the context keys the batched questions asked for. Questions use the noul primitive with `criteria.true` and `criteria.false` as `\{ what, examples \}` objects. The response is validated fail-closed and bodies are never logged.

### Finding

`src/types.ts` (`Finding`): rule id, category, domain, severity, band, probability, unit provenance, message, evidence, fix hint.

## Pipeline

`src/cli.ts` (Commander) calls `src/lint.ts`, which runs extract, judge, reduce, report.

- `src/scan/profiles.ts`: a profile is a scope. It picks files and rule domains and never changes a rule’s status.
- `src/rules/`: fail-closed loader and validator, the taxonomy copied from taste-training, and the question builder. `src/rules/code/` holds the rules that count, compare or measure.
- `src/extract/`: units from Markdown and MDX (mdast), TSX (oxc-parser), Tailwind class lists, style-capture output, and one `source` unit per TSX, JSX or CSS file.
- `src/map/`: `plan.ts` decides which rules apply to which unit and runs mechanical checks. `judge.ts` is the one stage lint and eval share. One request per unit carries every matching question, with a sha256 cache under `results/cache`.
- `src/reduce/`: bands, dedupe, scorecard, deterministic fixes, and `mechanical.ts` for regex and phrase matching.
- `src/report/`: tty, JSON, SARIF. `src/eval/`: corpus loader, precision and recall with Wilson intervals, calibration, threshold tuning, McNemar A/B.
- `data/rules/<domain>/<id>.yaml` are the shipped rules. `data/corpus/*.jsonl` are labelled units. `data/rule-drafts/` is never loaded.

## Glossary

One name per concept. Substituting a synonym splits the concept across the code.

- **Unit**: one extracted piece of text or one class list. A corpus row is an **item** until `unitFromItem` turns it into a unit.
- **Unresolved**: a value the extractor could not resolve, such as a Tailwind theme token.
- **Unknown**: the finding-level outcome when a rule cannot decide for a unit. Reported, never counted as pass or fail.
- **Band**: how sure a finding is: `act`, `review` or `silent`.
- **Severity**: how bad a finding is if real: `major` or `minor`. Set by the rule, independent of the band.
- **Mechanical / Jev / both**: the rule tiers. `both` means the mechanical part filters candidates and Jev decides.
- **Skipped**: a rule does not apply to the unit. **Negative**: an applicable check evaluated without a violation.
- **Request**: one logical provider evaluation. **Attempt**: one HTTP try. **Cached answer**: one reused rule probability.

## fix

Every rule carries `fix.hint`, printed under the finding for a person or an agent. Nothing in this package calls a text model. `fix.function` names a function in `src/reduce/fixes.ts` that `--fix` applies to each of the unit’s `fixRanges`. It never touches the quotes, braces, expressions or inline code around them.

## Non-goals

- No `choice` or `score` rules. The schema reserves the field.
- No Tailwind `@theme` parsing. Unknown tokens are `unresolved`, never guessed.
- No composite taste score. The scorecard is counts by category and domain.
- No baselines, review decisions or remediation exports. The findings, `--since` and SARIF are the record.

## Run contract

Preparation in `src/map/judge.ts` is shared by preview, execution and eval. A prepared judgement retains eligibility, mechanical negatives and skipped reasons. `LintResult.summary` is the one policy result; the exit code, text and JSON all consume it. JSON v1 keeps grouped `findings` and adds complete `ruleFindings`, `summary`, `scope` and `coverage`. The [TypeSafe](/typesafe) page holds the provider contracts.
